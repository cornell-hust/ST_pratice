# 调研纪要 3：中文社区实践经验（2026-09-22）

调研方式：ZCode 子代理中文检索（CSDN/博客园/知乎/TesterHome 等）。

## LLM 应用测试工程实践

- 批量评测标准流水线：测试集 JSON → 并发调用（限流）→ 规则打分 → 报告与版本 diff；规则评测（解析器能否解析）优先于 LLM 打分——cron 场景天然可判定；
- **一致性共识**：temperature=0 也不保证稳定（并发浮点非结合性、MoE 路由），需固定模型版本、控制并发、多次采样统计一致率——本作业把"一致率"本身作为测试维度；
- 断言策略聚焦"结构 schema + 解析后语义等价"，不逐字匹配表达式；
- 成本控制：评测集分层，核心 case 必过/回归集/边界 case。

## 用 LLM 生成单测的"假绿"分类学（反思素材）

博客园/知乎总结的四种"假绿"模式：过度 Mock 隔离真实逻辑、断言脆化绑定实现细节、假断言不校验返回值、AI 同时代码与测试时共享盲点导致覆盖率幻觉——写入报告"AI 反思"。

## NL→cron 已知失败模式（用例设计直接素材）

1. **星期数字映射混乱（最高频）**：Quartz/Spring 1=周日 vs Linux crontab 0/7=周日（博客园《cron 表达式的双重人格》）；
2. Quartz 中日/周字段不能同时为 `*`（其一须 `?`），LLM 极易混用两套约定；
3. 模型自身星期计算缺陷（OpenAI 社区 "GPT can not into weekdays?"）；
4. 5 字段与 6/7 字段（秒/年）混淆；`?/L/W/#` 方言符号泄漏；
5. 中文模糊表述："每两周""工作日""每隔一个工作日""月末"；
6. 现成参照：[huoyo/nlp2cron](https://github.com/huoyo/nlp2cron)（Java seq2seq，输出 Quartz 7 字段——方言混淆典型案例）。
