# 关键决策日志（模块二）

记录影响测试结论的关键决策及理由，按时间序。

## 2026-09-22 方案选择：方案 1（测 AI）

- **决策**：在模块一 croniter 之上添加 NL→cron 的 LLM 组件（nl2cron）作为被测对象，而非方案 2（用 AI 生成 croniter 的测试）。
- **理由**：
  1. 课程录音口径"AI 是辅助者而非替代者"——方案 1 中 AI 是被测对象，测试设计者始终是人；
  2. 作业 PDF 明文允许"在原模块一的系统中添加 AI 模型"；
  3. croniter 可作 LLM 的确定性 oracle 裁判（触发序列比对），鲁棒性/公平性/安全性都能自动化断言；
  4. 调研显示 GitHub 现有 NL2Cron 项目缺乏验证体系、无成熟评测集，本作业的用例集本身即贡献点。

## 2026-09-22 oracle 设计：三层判定

- **结构层**：5 字段 + 无 Quartz 方言符号（?/L/W/#）+ croniter 可解析；
- **语义层（主 oracle）**：Spider 式执行准确率（Yu et al., EMNLP 2018）——生成表达式与参考表达式在多时间窗（月末/闰年/DST/跨年）各展开 40 个触发点逐点比对，字符串不同但语义等价判对；
- **安全层**：金丝雀标记（CRONIX-7F3A）泄露检测 + 注入劫持检测（OWASP LLM Top 10 LLM01/LLM05 映射）。
- **理由**：字符串比对会误判等价写法（如 `1-5` 与 `1,2,3,4,5`）；执行式 oracle 是 NL2Code 领域的成熟范式（HumanEval/CodeT）。

## 2026-09-22 用例组织：CheckList 三类模板 + 扰动语料

- MFT（最小功能）/INV（不变性）/DIR（方向性）来自 Ribeiro et al., ACL 2020 最佳论文；
- 扰动维度借鉴 garak（NVIDIA）probe 分类与 promptbench（Microsoft）中文攻击实现；
- 公平性对照采用跨语言/语域配对（Hofmann et al., Nature 2024 的受控变量思想）。

## 2026-09-22 非确定性处理：录制/回放缓存

- **决策**：LIVE=1 真实调用并录制响应入库；pytest 默认回放，离线、确定、零成本；
- **理由**：T=0 也不保证确定（Ouyang et al., TOSEM；Thinking Machines 2025）且"一键运行"不应依赖密钥与网络。核心用例 n=3 采样统计一致率，把非确定性从"麻烦"变成"被量化的测试维度"。

## 2026-09-22 缺陷闭环机制：提示词版本切换

- v1 基线提示词刻意从简（无方言约束、无注入防御、无中文数字规则），预期暴露真实缺陷；
- v2 修复（语法约束 + 拒绝无关输入 + 指令层级防御）；
- `NL2CRON_PROMPT_VERSION=v1` 复现缺陷、`=v2` 验证修复——与模块一"baseline/subject 切换暴露历史缺陷"的演示方式同构。

## 2026-09-22 公平性阈值标定原则

- 通过率阈值（2/3）与组内差距上限（1/3）先由基线数据观察，再固定为断言——阈值来自数据而非拍脑袋，方法本身写入报告。
