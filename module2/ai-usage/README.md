# ai-usage/ — AI 使用披露（模块二）

本模块二即"AI 融合实践"，AI 的使用本身就是被考核对象，我们按以下原则使用并完整披露。

## 披露声明（四要素）

| 要素 | 说明 |
| --- | --- |
| **用途** | ① 文献与开源方案调研（见 `调研纪要/`）；② 测试工程脚手架与文档生成的辅助实现；③ 被测 LLM 组件所用模型（产业模型 API，作为被测对象而非测试者） |
| **范围** | AI 不代替人做测试决策：用例设计、oracle 判定标准、缺陷认定、修复方案均由小组成员评审确定；AI 生成的代码经人工逐文件审查后入库 |
| **人工修改** | 每个分片实现经"实现者 → 规格审查 → 质量审查 → 集成审查"流程，审查意见与修复见 Git 提交历史 |
| **验证方式** | 全部结论可离线复现：`python -m pytest -q`（回放缓存入库，无需 API Key） |

| `关键决策日志.md` | 方案选择、测试设计与提示词演进的关键决策及理由 |

## 教师口径对齐

课程录音明确："AI 应当是辅助者而非替代者，如果最终变成 AI 替代了人的测试工作，
并不是期望的结果。"本模块选择**方案 1（测 AI）**：AI 组件是被测对象，测试设计、
结果判定与质量结论始终由人来完成——这正是该口径下的正面示范。
